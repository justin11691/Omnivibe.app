Hardware Compatibility Matrix

OmniVibe Studio separates the Web Studio (instant browser 60fps shaders + generative soundscapes) from the Local Companion Bridge / Native Desktop App, which owns native OS UDP & DTLS 1.2 sockets for sub-50 ms local Wi-Fi smart-light sync.

Ecosystem / Model Status Transport Protocol & Requirements
Philips Hue Bridge v2 + Color Bulbs / Lightstrips / Play Bars Supported Entertainment API v2 (API ≥ 1.22), DTLS 1.2 PSK over UDP 2100 at 35 Hz. Requires an Entertainment Area (up to 10 lights, max 1 active area per bridge).
Govee LAN-Enabled Models (e.g. H6199, H61A0, H6072, H6056, H6159 with LAN API) Supported Local LAN UDP (multicast 239.255.255.250:4001, listen 4002, control 4003) + optional Razer/Dreamview 0xB1 mode + static-IP unicast fallback. Requires "LAN Control" toggled ON in Govee Home app.
WiZ Wi-Fi RGB / RGBTW Bulbs & Strips Supported Local raw JSON setPilot over UDP 38899 (broadcast 255.255.255.255 or static IP unicast with DHCP reservation recommended). Includes exponential smoothing.
Philips Hue Bridge v1 (Round BSB001) Unsupported Bridge v1 lacks Entertainment API & DTLS 1.2 support. OmniVibe Studio does not fall back to rate-limited REST polling.
Bluetooth-Only Bulbs (Hue Bluetooth without Bridge v2, Govee BLE-only) Unsupported Cannot receive high-rate LAN UDP/DTLS frames.
Govee H6006 / H605C & Cloud-Only Govee Models Unsupported These models do not expose Govee's local LAN Control toggle. OmniVibe never uses Govee's cloud HTTP API (10,000 req/24h cap) for live audio sync.
Matter over Thread / Wi-Fi & Bluetooth BLE Ambient Lamps Coming Soon Planned for future native bridge releases once high-frequency streaming profiles stabilize.
Pre-Flight Diagnostics Built In: The Local Companion Bridge automatically checks for UDP port 4002 conflicts (Home Assistant, Homebridge, Govee Desktop), active VPN adapters, and Wi-Fi/Ethernet dual-homing before scanning, and always supports direct Static-IP Unicast bypass.
